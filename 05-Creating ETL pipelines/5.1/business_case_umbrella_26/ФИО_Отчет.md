# Отчет по лабораторной работе №5.1

## Тема: Проектирование объектной модели данных. Проектирование сквозного конвейера ETL. Вариант 14.

**Выполнил:** ФИО

### 1. Цель работы
Развернуть среду оркестрации Apache Airflow с использованием Docker. Изучить структуру и принципы работы ETL-конвейеров (DAG). Осуществить прогнозирование данных с использованием ML-модели. Спроектировать архитектуру конвейера и реализовать индивидуальное задание.

### 2. Задание по варианту
**Вариант 14:**
* Прогноз: Варшава, 5 дней
* Трансформация: Группировка: среднее по рабочим дням
* Сохранение/Визуализация: Визуализировать таблицу

### 3. Исследование модельного кейса (`01_umbrella.py`)
Ознакомился со структурой DAG, который берет прогноз погоды, генерирует фейковые продажи и сохраняет результат в локальную файловую систему. Этот скрипт имеет следующие графики и операторы, работая как Sequential ETL пайплайн.

### 4. Реализация индивидуального задания (`variant_14.py`)
Был создан или модифицирован файл DAG `variant_14.py`, содержащий следующие узлы:
- `fetch_weather_forecast`: Получает данные из **Open-Meteo** (без ключа, координаты 52.2297, 21.0122 для Варшавы на 5 дней). 
- `clean_weather_data`: Очищает данные, восстанавливает пропуски (`ffill`), добавляет столбец `день недели` и `is_working_day`.
- `visualize_table`: Отбирает только рабочие дни (`< 5`), группирует их, вычисляет среднее значение и сохраняет таблицу, визуализируя её.
- Окончание пайплайна выполняет `merge` данных и тренирует `ml_model.pkl` с использованием `LinearRegression`.

Архитектура разработанного решения представлена на схеме `archi.png` (лежит в репозитории).

### 5. Дополнительная аналитика в Jupyter Notebook
Был составлен ноутбук `прогноз_продаж.ipynb`, в который загружена модель `ml_model.pkl`, созданная Airflow. На основе средней температуры по рабочим дням в Варшаве (которая равняется примерно 8.3°C), была составлена оценка прогнозируемых продаж с помощью метода `model.predict()`.
